### What this is and what this isn't

This document is a deterministic, descriptive map of the prism Go module under
`modules/programs/prism/prism/`. It records what the codebase contains today —
packages, exported symbols, file and function sizes, isolation- and
harness-coupling sites, the per-spawn data flow, lifecycle traces, external
boundaries, and the test landscape — in a structure designed to be regenerated
on a future commit so changes are visible by diff. It is the foundational
artefact for a planned series of narrow architecture reviews (duplication,
layering, error-handling, concurrency, harness coupling, isolation coupling,
A/B-readiness). Subsequent reviews will read this document instead of
re-discovering the codebase.

This document contains zero opinions, zero refactor proposals, and zero
"we should" recommendations. Where two sites look duplicated, both are listed
without judgment. Where an answer is unknown, the entry is marked
`[uncertain — <reason>]` rather than guessed. The narrow reviews that follow
will form opinions; this document only provides the corpus.

Regenerate when stale. Section 14 records the methodology so a future
regeneration is comparable.

## 6. Isolation-mode coupling map

Every site under `modules/programs/prism/prism/` (excluding `_test.go`) that mentions any of `podman`, `bwrap`, `sandbox-exec`, `IsolationHost`, `IsolationMode`, `IsolationPodman`, `IsolationBwrap`, `IsolationSandboxExec`, `--isolation`, `host_mode`, `HostMode`, or `hostMode` by name or via a string literal. The list is exhaustive against that grep set; comment-only mentions are included because they document the architectural intent at a site (which a structural review needs).

**Coupling tightness legend:**

- `surface` — log message, comment, or string literal that names a mode but does not affect control flow.
- `shape` — `switch` / `if` branches on the mode value, or a function whose argument list includes a mode.
- `structural` — mode-specific data flow (separate code paths, separate types, separate runtime resources).

**Modes touched legend:** `[podman]`, `[bwrap]`, `[sandbox-exec]`, `[host]`, `[all]` (all four), or `[agnostic]` (defines or accepts the mode but does not branch on it).

## 10. Lifecycle map

For each top-level prism subcommand, the function chain and side-effects.

### 10.1 `prism spawn`

**Function chain:** `cmd/root.go:Execute → cmd.spawnCmd → cmd/spawn.go:runSpawn → resolveIsolationMode → checkBwrapPlatform → checkSandboxExecPlatform → CheckAvailability/checkBwrapConcurrencyCap → config.LoadProfiles → config.ContainerConfigForRole/BuildConfigContent → container.WriteOpencodeConfig (bwrap only) → session.SpawnSession → session.Create/setupFullLayout (LayoutFull) → tmux.NewSessionDetached → fork "prism event tmux-session-start" → tmux.NewWindow ×3 → session.StartSidecarWithOpts → exec.Command(self, "sidecar", …) → WaitForReady`.

**Side-effects:**

- DB writes:
  - `agent_status`: row seeded with `root_agent_name`, `instance_id`, `harness`, `host_mode`, `isolation_mode`. State transitions: idle → active.
  - `sessions`: row inserted by `tmux-session-start` event hook.
  - `agent_events`: `tmux_session_start` event written.
  - port allocation in `agent_status.harness_port`.
- FS creations:
  - `~/.local/state/prism/run/<session>/sidecar.sock` (host-API)
  - `~/.local/state/prism/run/<session>/sidecar.pid`
  - `~/.local/state/prism/run/<session>/sidecar.ready` (podman only, written by sidecar after WaitHealthy/CreateSession)
  - `~/.local/state/prism/run/<session>/sidecar.log`
  - `~/.local/state/prism/run/<session>/agent-startup.log`
  - `~/.local/state/prism/run/<session>/agent-run.log` (bwrap only)
  - `~/.config/opencode/<sessionDirName>/opencode.json` (bwrap only — written before pane open)
  - For container mode: `~/.local/share/opencode/prism-sessions/<container-name>/storage/` (per-session opencode state; Darwin virtiofs WAL-mode workaround).
- Tmux operations: new session, three windows (`edit`/`agent`/`term`), agent pane spawns the per-mode command (`podman attach`, `prism agent-run`, or direct opencode).
- Container/sandbox creations:
  - `IsolationPodman`: `podman run` creates a container named `prism-<session>` (or `prism-<parent>-review-<N>-<role>` for review).
  - `IsolationBwrap`: bwrap process launched by `prism agent-run` in the tmux pane.
  - `IsolationSandboxExec`: sandbox-exec process via `syscall.Exec` from `prism agent-run`.
  - `IsolationHost`: opencode runs directly in the tmux pane.
- Network calls:
  - Sidecar binds Unix socket at `sidecar.sock` (host-API server).
  - Sidecar binds TCP listener on 0.0.0.0:0 (host-API TCP variant; see `internal/sidecar/sidecar.go:364`).
  - Sidecar dials the harness HTTP endpoint (`http://127.0.0.1:<port>/global/health`, `/session`, `/session/<id>/message`, etc.).
  - Sidecar opens an SSE stream against the harness (`/event`).

### 10.2 `prism cleanup`

**Function chain:** `cmd/root.go:Execute → cmd.cleanupCmd → cmd/cleanup.go:runCleanup → (interactive: confirmModel/cleanupModel TUIs) → headlessCleanup per-session → resolveIsolationMode (from DB row) → killSidecar → KillReviewSessionsForParent (if parent has a review group) → stopAndRemoveChildContainers (recursive for groups) → removeContainerIfExists → tmux.KillSession → DB cleanup`.

**Side-effects:**

- DB writes:
  - `agent_status.ended_at` set.
  - `sessions.ended_at`, `sessions.end_state` set via `db.UpdateSessionEnded`.
  - `bus_messages` for the session purged via `db.PurgeBusMessages`.
  - `pending_merges` for the session abandoned via `db.AbandonWatchingMerges`.
- FS operations:
  - `~/.local/state/prism/run/<session>/` directory removed (best-effort).
  - `~/.config/opencode/<sessionDirName>/opencode.json` removed.
- Tmux: `tmux kill-session`.
- Container/sandbox: `podman stop --time 10 <name>`; `podman rm --force <name>`. For bwrap/sandbox-exec sessions the `podman` calls return "no such container" and are silently tolerated.
- Network: a host-API proxy fallback exists (`cmd/cleanup.go:headlessCleanup_Proxy`) — if the local sidecar is unreachable cleanup proxies to the host sidecar.

### 10.3 `prism merge`

**Function chain:** `cmd/root.go:Execute → cmd.mergeCmd → cmd/merge.go:runMerge → isolationCheck (proxy to host-API if inside bwrap) → gh pr view → db.EnqueueMerge → returns immediately while mergequeue.Watcher (in coordinator's sidecar) drives it`.

**Side-effects:**

- DB writes:
  - `pending_merges`: row inserted with `pr`, `session_name`, `instance_id`, `queue_position`, `status='queued'`.
- Network calls:
  - `gh pr view <pr> --json …` to validate the PR exists.
  - When proxied (bwrap): host-API `/merges/enqueue` over the per-session Unix socket.
- The actual merge happens asynchronously inside the coordinator's sidecar (see 10.7 below).

### 10.4 `prism restore`

**Function chain:** `cmd/root.go:Execute → cmd.restoreCmd → cmd/restore.go:Restore → db.AllActiveStatus → for each ended session matching restore criteria → restoreProjectSession → resolve isolation mode (with v10 back-compat) → kill stale sidecar PID → mint fresh instance_id → re-seed agent_status → fork "prism event tmux-session-start" → session.Create/setupFullLayout → session.StartSidecarWithOpts`.

**Side-effects:**

- DB writes: same shape as spawn, but on existing sessions (`UpsertStatus` with state="idle"; `ClearEnded`; `SetInstanceID` with new UUID).
- FS operations: same as spawn.
- Tmux: re-creates the tmux session if missing.
- Container/sandbox: starts fresh per-mode instance (the previous container has already been removed).
- Network: same as spawn.
- Includes a circuit-breaker check (`config.SidecarCircuitBreakerThreshold`): a session that has had N consecutive sidecar failures is skipped.

### 10.5 `prism reset`

**Function chain:** `cmd/root.go:Execute → cmd.resetCmd → cmd/reset.go:runReset → exec.Command(self, "launch") → resetRemovePodmanContainers → exec.LookPath("podman") → exec.Command("podman", "ps", …) → exec.Command("podman", "rm", "-f", …) → db.MarkAllEnded`.

**Side-effects:**

- DB writes: `agent_status.ended_at` set on every active row (`db.MarkAllEnded`).
- FS: `~/.local/state/prism/run/` directory cleared (best-effort).
- Tmux: kills all `prism-*` sessions.
- Container/sandbox: `podman ps` + `podman rm -f` for every container with the `prism-` prefix. bwrap/sandbox-exec sessions are not directly killed by reset (they exit when the tmux pane is killed).
- Network: none directly.

## 13. Glossary

Domain terms used in the codebase that a new reader wouldn't know from Go-stdlib alone. ≤2 sentences each.

- **agent-run** — `prism agent-run`, the internal subcommand that exec's bwrap or sandbox-exec from a tmux pane. The bwrap path forks a child with PTY-pair allocation; the sandbox-exec path uses `syscall.Exec` directly.
- **agent_events** — SQLite table in `prism.db` capturing every event the sidecar receives from the harness. Schema in `internal/db/db.go:115-127`.
- **agent_status** — SQLite table holding one row per active or terminal session. The dashboard, `prism status`, and `prism cleanup` all read from this table. Schema in `internal/db/db.go:154-173`.
- **archive path** — directory `~/.local/state/prism/archives/<instance_id>/` containing a snapshot of the session's opencode state plus metadata. Built by `internal/archive` and converted to pi-mono format by `internal/piexport`.
- **bare+worktree layout** — repo layout where `<bare-path>` (a `.git` directory) is checked out separately from the working trees, which live as siblings under the same parent. Created by `internal/git.ConvertToBare` and `CloneWorktree`.
- **bus** — the `bus_messages` SQLite table plus the polling loop in the sidecar that delivers cross-session prompts. Used by mergequeue notifications, review-complete prompts, and any `prism prompt --bus` invocation.
- **bwrap** — bubblewrap, the Linux user-namespace sandbox. One of the four isolation modes; the long-term primary on Linux.
- **circuit breaker** — restore guard in `cmd/restore.go` that skips a session if it has had N consecutive sidecar failures (`config.SidecarCircuitBreakerThreshold`, default 3).
- **compacting** — agent state entered when opencode runs context compaction (summarising old turns to free context). Captured by the `compaction` event type and displayed as a non-terminal state in the dashboard.
- **coordinator** — the special agent role spawned on the `main` branch of a repo, intended to delegate to worker sessions. Identified by `agent_status.root_agent_name = 'coordinator'`. Only one active coordinator per repo (enforced by partial unique index v11→v12).
- **doom loop** — heuristic detection of the assistant repeating the same tool call or text. Reported as the `doom_loop_detected` event type; aggregated by `prism stats doomloops`.
- **group** — a `session_groups` row registered for a parent session that fans out to child sessions (today only used by review). The `agent_status.group_id` column links members. `db.GroupCompleted` reports whether all members reached terminal.
- **harness** — pluggable adapter (`internal/harness.Harness`) that teaches the sidecar how to drive a specific agent runtime (opencode today; PI in the planning queue per #691). Each implementation handles container-command, health-check, prompt-delivery, session-creation, and event-stream mapping.
- **harness_session_id** — the harness's own session identifier (e.g. opencode SID). Persisted as `agent_status.harness_session_id` and `agent_events.harness_session_id`. Renamed in migration v14→v15 from `opencode_sid`.
- **host mode** — `IsolationHost`; opencode runs directly in the tmux pane with no sandbox. The deprecated `--host-mode` flag is an alias.
- **host-API** — per-session Unix-socket HTTP server in the sidecar. Lets sandboxed processes proxy requests to the host (`prism cleanup`, `prism merge`, etc. running inside a bwrap sandbox use this to reach the host sidecar).
- **incarnation** — one run of a session with a specific `instance_id`. Restoring a session mints a new instance_id; events from the old instance remain queryable via `agent_events.instance_id`.
- **instance ID** — UUID generated per spawn-or-restore. Persisted on `agent_status.instance_id`, `sessions.instance_id`, and `agent_events.instance_id` (FK to `sessions`). Used to dedup messages on the bus and to scope per-incarnation queries.
- **isolation mode** — one of `podman`, `bwrap`, `sandbox-exec`, `host`. Selected via `--isolation` or persisted from `config.json`. See section 6.
- **merge queue** — local serial merge mechanism (`pending_merges` table; `internal/mergequeue.Watcher`). Coordinator's sidecar polls the queue and drives each PR through `gh pr merge --squash` (or `gh pr update-branch` when behind).
- **opencode_sid** — legacy column name for `harness_session_id`. Renamed in migration v14→v15.
- **pi-mono** — the v3 JSONL trace format produced by `internal/piexport.Translate` from an opencode raw archive. [uncertain — what "pi-mono" stands for / external context]
- **prism-** prefix — naming scheme for podman containers and tmux sessions managed by prism. Used by `prism reset` to identify what to clean.
- **profile** — per-environment model selection (`profiles.json`). A profile maps role → primary model + variants.
- **PR-C** — the architectural redesign of review session topology (5 independent top-level sessions per round) referenced in `internal/review/review.go` package doc.
- **proxy** (verb / proxy-spawn / proxy-prompt) — bwrap-sandbox detection: when a CLI subcommand runs inside a sandbox it proxies the request to the host sidecar via the host-API socket. See `cmd/hostapi.go` and the host-API endpoint handlers in `internal/sidecar/sidecar.go`.
- **readiness gate** — `internal/session.WaitForReady` blocks the spawning process until the sidecar observes the first SSE event from the harness (i.e. the agent actually came up). #1051.
- **review group** — a `session_groups` row whose parent_session has at least one `agent_status` row matching `<parent>~review-<N>-<role>`.
- **reviewing** — non-terminal state entered when a worker session calls `prism review`. Cleared back to `active` on FAIL verdict, transitions to `finished` on PASS.
- **role** — short for "agent role" (`coordinator`, `worker`, `review-goal`, `review-code`, `review-security`, `review-qa`, `review-context`, plus user-defined roles in `~/.config/opencode/agents/`).
- **sandbox-exec** — Apple's SBPL-profile sandbox; one of the four isolation modes. Macros mirror bubblewrap's allow-lists (see `internal/container/sandbox_exec.go`).
- **scratchpad** — a special-purpose session named `scratchpad` for ad-hoc work. `internal/session.IsMetaSession` identifies it.
- **sidecar** — long-running per-session process that drives the harness and writes events. Implemented in `internal/sidecar/`.
- **sidecar.ready** — file at `~/.local/state/prism/run/<session>/sidecar.ready`. Touched by the sidecar after `WaitHealthy` + `CreateSession` succeed (podman mode). The agent pane's readiness-wait loop polls it.
- **sun_path** — the kernel's sockaddr_un path-length limit (108 bytes Linux, 104 bytes Darwin). Per-session host-API socket paths are kept under 104 bytes via a 12-hex SHA-256 prefix scheme (#1050).
- **TUI** — terminal user interface; here, the opencode TUI (running in container or pane) and the prism dashboard TUI (`internal/dashboard/`).
- **virtiofs** — Darwin podman uses a virtiofs share to expose the host's filesystem; SQLite WAL semantics are unreliable across this share, so per-session opencode state lives in a per-container subdirectory rather than the shared root (see `internal/container/container.go:1226-1228`).
- **WaitHealthy** — `(*container.Manager).WaitHealthy`; podman-mode polling of `GET /global/health` (specifically chosen over `/` to avoid the opencode UI catch-all proxy).
- **worker** — non-coordinator agent role spawned on a feature branch. Default for any non-main spawn.
- **worktree** — a git worktree; one per spawned session. Lives alongside the bare repo under the same parent.

   for f in $(find modules/programs/prism/prism -name '*.go' -not -name '*_test.go'); do
     awk '
       /^func / { name=$0; start=NR; depth=0 }
       /^func / || depth > 0 {
         for (i=1; i<=length($0); i++) {
           c = substr($0,i,1)
           if (c == "{") depth++
           else if (c == "}") {
             depth--
             if (depth == 0 && start) {
               sz = NR - start + 1
               if (sz >= 100) print sz "|" FILENAME ":" start "|" name
               start = 0; break
             }
           }
         }
       }

- Display-only references (dashboard column formatting, list-sessions output, stats tables) are not enumerated line-by-line in sections 6 and 7; they are summarised in subsection paragraphs.
- The inventory was generated on Linux (`linux/amd64`); platform-specific code paths (Darwin sandbox-exec) were verified by reading source rather than running.
